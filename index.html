업무 과제
IDC·CDN·검색·메시징·유지보수·라이선스는 대상과 갱신 주기가 다릅니다. 기술 운영 일정과 비용 처리 일정이 어긋나지 않도록 현황을 함께 확인해야 했습니다.
담당 업무
  • 부서 예산관리 파일을 유지하고 월별 예산·실적 현황을 직접 정리·보고
  • 예산 부족 및 일정 변경에 따른 예산 전용·이월 신청
  • CDN·검색 솔루션 재계약, 메시징 예산 이월, 솔루션 유지보수와 라이선스 갱신 실무
  • 월별 실비 마감·세금계산서·비용보고 자료 정리와 유관 부서·협력사 일정 조율
  • IDC 실물 서버 목록의 자산 현황 반영과 운영 상태 확인·공유

CASE 02 · 2026.06–09

SSL/TLS 인증서 배포·현황관리 자동화

25대 운영 적용

서버별로 달랐던 인증서 교체를 사전 검증·백업·배포·응답 확인·복구의 공통 절차로 만들고, 인증서 상태를 중앙에서 확인하도록 구성했습니다.

문제
Apache·Tomcat·Resin·NetFUNNEL의 인증서 경로와 재기동 방식이 달랐습니다. 파일 교체 성공만으로 실제 서비스에 새 인증서가 반영됐다고 판단할 수 없었습니다.
설계·구현
  • 실행 프로세스와 활성 설정을 탐지해 실제 사용 중인 인증서 경로 확인
  • dry-run → canary 1대 → 순차 배포 → 승인 시간대 활성화로 변경 범위 제어
  • 파일 배치와 재기동을 분리하고, SHA-256 지문·실제 443 응답까지 검증
  • 검증 실패 시 기존 인증서로 자동 복구하도록 백업·롤백 절차 구성
  • 만료일과 수집 지연을 확인하는 HTML/JSON 현황 대시보드 구성
운영 결과
2026년 9월 정기 교체에서 운영 대상 25대에 적용했습니다. 작업 중 발견한 Resin 명령과 인증서 체인 조립 오류는 자동 롤백 후 수정·재배포해 확인했습니다.
남긴 기준
정상 여부를 배포 명령의 종료값이 아닌 실제 서비스 응답으로 판단합니다. 실행·승인·검증·복구 절차를 운영 가이드로 남겨 다른 담당자도 같은 기준으로 확인하도록 했습니다.

근거 · SSL 자동 배포 실행 가이드, 롤백 가이드, 현황 대시보드 명세, 2026년 업무보고. 25대는 9월 운영 적용 기준입니다.

Ansible · Python · Shell · OpenSSL | 직무 연결 · 운영 자동화 / 현황 관리 / 안전한 변경

CASE 03 · 2024–2026

서버 보안 기준선·ISMS 조치와 운영 증적

ISMS CONTROL

위험평가와 진단 결과를 실제 서버 조치로 연결하고, 서비스 영향 확인부터 재점검·잔여 위험 기록까지 수행했습니다.

판단 기준
보안 설정을 일괄 변경하면 서비스 계정의 파일 접근이나 WEB/WAS 동작에 영향을 줄 수 있습니다. 실제 소유권·서비스 구조·재기동 필요 여부를 확인하고 적용 순서를 정했습니다.
직접 수행
  • Linux 홈·로그 파일 권한, 비밀번호 정책과 Apache/Tomcat 노출 설정 조치
  • Windows 누적 보안 업데이트, Rocky Linux Golden Image 점검·기준 반영
  • 변경 전 백업, 설정 문법 검사, 재진단으로 적용 결과 확인
  • WEB/WAS·운영도구 위험조치와 결과 기록, 잔여 항목 추적
확인 결과
2025년 ISMS 심사·결함 조치를 기한 내 수행해 인증 유지에 기여했습니다. 2026년 7월 보고에는 Linux 잔여 위험조치 100%, Windows 서버 90% 진행이 기록돼 있습니다. 해당 시점의 조치 진행률이며 전사 보안 수준을 의미하지 않습니다.
참여 범위
서버 보안 조치와 운영 증적 관리 경험입니다. 조직 전체의 통제 설계·감사 책임이나 공용 위험조치 계획서 전체를 개인 성과로 제시하지 않습니다.

근거 · 개인 성과평가·KPI, 서버 위험조치 기록, 2026년 7월 업무보고. 공용 위험조치 이행계획은 참여 범위를 설명하는 보조 근거입니다.

훈련 범위

점검 내용

직무 활용
절차가 존재하는 것과 비상시에 실제로 실행할 수 있는 것은 다르다는 점을 확인했습니다. 연락망·역할·복구 절차를 현행화하는 경험을 기반으로, 금융권 DR 환경의 실제 전환·복구 검증 역량을 확장하고자 합니다.
